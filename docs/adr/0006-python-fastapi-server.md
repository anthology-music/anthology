# ADR 0006: Python with FastAPI for the server

- Status: Accepted
- Date: 2026-10-09

## Context

The server orchestrates downloads, tagging, transcoding, fingerprinting, MusicBrainz lookups, sheet-music processing and a WebSocket protocol. Most tools in this field (music21, pyacoustid, Verovio bindings, librosa) are Python libraries.

## Decision

The server is written in **Python 3.12+** with **FastAPI** (REST and WebSocket), **pydantic** v2 and **SQLAlchemy 2 async**, managed with **uv**.

## Alternatives considered

- **Node.js/TypeScript:** one language with the client, but most media and music libraries would have to be called as external processes.
- **Go/Rust:** better raw performance, but again few native music libraries; slower iteration.

## Consequences

- Media libraries are used directly as libraries instead of parsing command-line output (except copyleft ones, see ADR 0004, and download tools for commercial streaming services, which run in separate source services, see ADR 0017).
- Async throughout; CPU-heavy work (fingerprints, analysis, OMR) runs in process pools or separate services.
- OpenAPI is generated by FastAPI and used to generate the client's TypeScript types.
